# 4.0.5 phases 1–5: implementation checkpoint

## Architecture audit
The application is a Java 17 HTTP backend with a plain JavaScript/CodeMirror 5 frontend. Server.java routes project, compiler, debugger, recovery and GitHub APIs. Runner.java launches javac/java; Debugger.java uses jdb. Share uses a dedicated pinned TLS 1.3 transport, authenticated sessions, host approval and an RGA document model with per-document local operation history. ShareDiscovery.java supplies LAN discovery. Mobile.java serves web-mobile through the existing backend. It is not an Android-native compiler. docs/ contains the public website, including Lark Preview/Flow descriptions. package.sh embeds both UIs in the JAR; packaging/ and .github/workflows/rebuild-release.yml manage distribution. No native Android project was found in this checkout.

## Implemented in this checkpoint
- Share: capture collaborative undo/redo shortcuts; retain local operation history; reject stale responses after session changes; clear native history on entry/exit; pending/role/presence summary.
- LAN: actual adapter names, IPv4 prefixes, active/loopback/suitability metadata, recommended adapters; pinned TLS connection probe with subnet hints and readable refusal/timeout/identity errors. Probe reveals no source and grants no participant access.
- Typing: common Java member suggestions for System.out, String, Scanner, lists and Math, shared across desktop/mobile. Comment/string suppression. This is heuristic assistance, not full semantic completion or a language server.
- Desktop: mkdir now observes Share's file structure lock. Existing GitHub authentication checks pass; no new GitHub authentication repair claimed.
- Mobile: corrected nested project response, invalid .java class-name stripping, dirty-on-open and save race bugs; save before navigation; duplicate-file protection; undo/redo, search, member completion, rename/delete and symbol buttons; bounded editor viewport; compact touch UI styling.

## Validation
package.sh builds successfully with Java 17. ShareCheck: 67 checks; ShareEditingCheck: 326 checks; GitHubAuthCheck passes. JavaScript Share document: 601 checks; scroll regressions, parser and new typing checks pass. Edited JavaScript parses and git diff --check passes.

## Remaining work / release blockers
Phases 1–5 are NOT complete. Real keyboard/browser tests for the reported repeated-z defect, composition, file switching and simultaneous editing are still required. The shortcut fix is implemented but not demonstrated on the affected machine. Full semantic completion, configurable pairing, measured typing benchmarks and the application-wide button audit remain. Mobile still needs a complete redesign, per-file undo persistence, folders, debugger controls, authenticated Share integration and secure remote execution redesign. Existing Mobile uses HTTP LAN pairing and host processes without a security sandbox; it must not be described as a secure remote execution service. Java execution was not verified on phone/tablet/browser devices. APK, website and release phases are deferred. No release version bump, merge, deployment or publication is included.
